# 5. n8n: workflows, variables, webhooks

n8n is the orchestrator. It knows nothing about YAML or the Confluence storage format: every engine call is an HTTP Request.

| Workflow | Trigger | What it does |
|---|---|---|
| **01 · Ingest** | `POST /webhook/docsync/gitlab` - GitLab Push Hook of service repositories | checks `X-Gitlab-Token` and the branch, `POST /api/v1/ingest`; on `PROPOSED/NEEDS_REVIEW` - a notification with the MR, pages and approve link; on `FAILED` - an alert |
| **02 · Publish** | `POST /webhook/docsync/model` - MR/Push Hook of the `architecture-model` repository; `GET /webhook/docsync/approve?run=<id>` - approve link | `POST /api/v1/publish` or `/runs/<id>/approve`, then `/api/v1/audit`, a summary notification; the approve webhook replies with the report |
| **03 · Reminders** | cron `0 10 * * 1-5` | `GET /api/v1/runs?status=PROPOSED`, older than 1 day → reminder |
| **99 · Errors** | Error Trigger (set as `errorWorkflow` of the others) | an alert with the workflow name and a link to the execution |

The JSON in `n8n/workflows/` is generated by `python n8n/build_workflows.py` - edit the script, not the JSON.

## n8n environment variables

| Variable | Value |
|---|---|
| `DOCSYNC_ENGINE_URL` | `http://docsync:8088` (compose) / engine URL |
| `DOCSYNC_API_TOKEN` | the same as the engine's `DOCSYNC_API_TOKEN` (empty - no check) |
| `GITLAB_WEBHOOK_SECRET` | Secret token of the GitLab webhooks (empty - no check, demo only) |
| `DOCSYNC_NOTIFY_URL` | where to POST `{text, level, source}`: a Slack Incoming Webhook, a Teams/Mattermost webhook, a Telegram bot bridge, or `http://docsync:8088/api/v1/notify` (demo: log + `GET /api/v1/notifications`) |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` | Code nodes read `$env.GITLAB_WEBHOOK_SECRET` |

## Import

```bash
./n8n/import.sh          # import:workflow --separate + publish/activate + container restart
```

In the n8n UI (http://localhost:5678) on first login n8n asks to create an owner account - it is a local instance, create any. The workflows are already active; executions are visible under Executions.

## GitLab webhooks (production)

| Where | Event | URL | Secret |
|---|---|---|---|
| the group with services (or every project) | Push events, branch `main` | `https://n8n…/webhook/docsync/gitlab` | `GITLAB_WEBHOOK_SECRET` |
| the `architecture-model` project | Merge request events + Push events (`main`) | `https://n8n…/webhook/docsync/model` | the same |

## Notifications: Slack and Telegram, approval from Telegram

n8n posts every notification to `DOCSYNC_NOTIFY_URL` as `{text, level, kind, runId?, mrUrl?, ...}`. By default this is the
engine's `/api/v1/notify`, which fans the message out to every configured sink:

| Sink | Setting | Behaviour |
|---|---|---|
| log | always | `data/notifications.log`, `GET /api/v1/notifications` |
| Slack | `SLACK_WEBHOOK_URL` (Incoming Webhook) | plain `text` |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | `text`; a `proposed` notification gets inline buttons **✅ Approve / ❌ Reject / 🔗 Open MR** |

(You may also point `DOCSYNC_NOTIFY_URL` straight at a Slack Incoming Webhook - the payload has `text` - but then Telegram buttons are not available.)

**Approval from Telegram.** The engine long-polls the Bot API (`getUpdates`), so no public URL is needed. A button press is accepted only from `TELEGRAM_CHAT_ID` and, if `TELEGRAM_ALLOWED_USERS` is set, only from those usernames/ids. *Approve* calls the same n8n approve webhook as the link in notifications (`DOCSYNC_APPROVE_INTERNAL_URL`, inside Docker `http://n8n:5678/...`), so merge → publish → audit → notifications run exactly as for the link. *Reject* marks the run `REJECTED`. The original message is frozen (buttons removed, "Approved by @user" appended) and the publish report is posted as a reply. Commands in the chat: `/pending` lists runs waiting for approval with buttons, `/status` shows engine health.

Setup: create a bot with @BotFather, add it to the approvals chat (for groups: disable privacy mode or make it admin so it sees `/pending`), get the chat id (e.g. forward a message to @userinfobot or read `getUpdates`), fill the `.env` variables and restart the engine. `TELEGRAM_POLLING=false` disables the poller (e.g. for a second replica).

## Notification (example)

```
📄 DocSync: orders-service - 2 architecture changes (PROPOSED).
Model MR: https://gitlab…/arch/architecture-model/-/merge_requests/57
Pages: Orders Service - системный анализ; Billing Service - системный анализ; Сценарий: оформление заказа; Payments - обзор домена
Approve without GitLab: https://n8n…/webhook/docsync/approve?run=72e4c9d5-…
```

For Slack it is enough to put an Incoming Webhook into `DOCSYNC_NOTIFY_URL` - the payload already contains `text`. To route to different channels per domain, add a Switch node on `$json.service_id` in WF-01 - the engine returns it in the ingest response. If you prefer buttons to a link - replace the HTTP Request with a Slack node using *Send and Wait for Approval* and call `/approve` after it.
